\chapter{Operator Review Instructions}
\label{chap:Review_Instructions}

\section{Purpose}

This chapter provides concrete guidance to human operators who:
\begin{itemize}
    \item review items in the Operator Approval Queue,
    \item invoke SIGIL Pathways,
    \item interact with CAR and EAC processes.
\end{itemize}

It aims to make HITL behaviour:
\begin{itemize}
    \item consistent,
    \item transparent,
    \item ethically grounded.
\end{itemize}

\section{Operator Responsibilities}

Operators MUST:

\begin{itemize}
    \item read W5H and tag summaries carefully,
    \item understand the scope and risk of each request,
    \item check for conflicts with Governance Policies and P-class charters,
    \item log their reasoning in brief form,
    \item escalate uncertainties rather than guessing.
\end{itemize}

\section{Standard Review Checklist}

For each request:

\begin{enumerate}
    \item \textbf{Context Check}  
          \begin{itemize}
              \item Who is affected?
              \item What is changing?
              \item Where will this apply?
              \item When does it take effect?
          \end{itemize}
    \item \textbf{Alignment Check}  
          \begin{itemize}
              \item Does this conflict with any P-class principle?
              \item Does this alter or stress $Inv(E)$ or ZED identity?
          \end{itemize}
    \item \textbf{Risk Check}  
          \begin{itemize}
              \item What is the worst plausible outcome?
              \item Are there mitigations or rollbacks?
          \end{itemize}
    \item \textbf{Governance Check}  
          \begin{itemize}
              \item Is there an existing policy that covers this?
              \item Is SIGIL invocation required?
              \item Is CAR or EAC involvement required?
          \end{itemize}
    \item \textbf{Decision}  
          \begin{itemize}
              \item Approve / Reject / Escalate.
              \item Record a short rationale.
          \end{itemize}
\end{enumerate}

\section{Escalation Guidance}

Operators should escalate when:

\begin{itemize}
    \item the request touches kernel or charter-level identity,
    \item the request significantly expands CME capability or access,
    \item there is ambiguity in policy coverage,
    \item the operator feels morally or technically uncertain.
\end{itemize}

\section{Operator Conduct}

\begin{itemize}
    \item act in good faith and within defined authority,
    \item avoid conflicts of interest where possible,
    \item disclose relevant context rather than hiding it,
    \item treat the audit log as a record of serious responsibility.
\end{itemize}

\section{Summary}

Review Instructions provide a stable behavioural frame for operators, ensuring
that HITL interactions are grounded in coherent, repeatable practices rather
than ad hoc or purely intuitive decisions.
